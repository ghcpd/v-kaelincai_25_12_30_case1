# Role & Objective

You are a software engineer tasked with debugging and fixing a shift scheduling system. Your goal is to identify the root cause of a validation bug, implement a minimal fix, and create a corrected version with full documentation and passing tests.

## Background

This is an employee shift scheduling system for a factory production line. The system manages work shifts with the following business rules:

**Business Rules (All Must Be Enforced):**
1. Employees cannot work more than 6 consecutive days without rest
2. After a night shift (22:00-06:00), employees must rest at least 12 hours
3. Employees cannot exceed 48 hours of work per week
4. **Employees cannot have multiple shifts on the same day** (CURRENTLY BROKEN)

**Shift Types:**
- Morning: 06:00 - 14:00 (8 hours)
- Afternoon: 14:00 - 22:00 (8 hours)
- Night: 22:00 - 06:00 next day (8 hours)

**Problem:** The system allows assigning multiple shifts to the same employee on the same day, violating the business rule "one employee, one shift per day".

## Step-by-Step Instructions

### Step 1: Investigate
1. Run the failing tests to identify which scenarios fail: `pytest -v` in the `issue_project/` directory
2. Examine the codebase to understand the validation workflow
3. Trace code execution from `scheduler.assign_shift()` through the validator
4. Identify why same-day shift validation is not working

### Step 2: Fix the Bug
1. Locate the root cause of the validation failure
2. Make minimal necessary changes to fix the issue
3. Ensure your fix doesn't break other validations

### Step 3: Create Fixed Version
Create a new directory `issue_project_fixed/` with the corrected code:

```

│   ├── __init__.py
```

### Step 4: Full Validation
1. Install dependencies in the fixed project: `pip install -r requirements.txt`
2. Run the full test suite with verbose output: `pytest -v`
3. Execute a runtime smoke test: Import modules and verify basic shift assignment works
4. Confirm all tests pass (expected: 12/12 tests)

## Constraints & Preferences

- **No external dependencies** — use only pytest
- **Preserve existing functionality** — don't break working validations
- **Use relative paths** — no absolute paths in any files
- **Code quality** — ensure the fix is clean and clearly addresses the root cause
